# 字灵巨字 / 剪影排版：为何难、可走的技术路线

## 1. 与「优秀字排版」的根本差异

产品级排版（书籍、杂志、UI）通常依赖：

- **成形后的几何**：每个 glyph 已是最终轮廓，布局引擎只算**盒模型**（advance、kerning、line break、hyphenation）。
- **单一坐标系**：整段文字在同一 affine 变换下，不混合「每字独立物理 + 全局 mask」。

字灵当前路径是：**N 个粒子 + 离散格 + mask 可走域 + 实时谐波/流体**，等于把「排版」和「多体约束动力学」绑在一起。粒子数常接近可走格数，**共格**在信息论上不可避免，只能靠分离、截断与牺牲动态来换稳定。

因此不是「看起来不难」，而是**问题类型不同**：我们做的是 **约束密铺 + 动画**，不是 **流式文本盒**。

## 2. 可借鉴的生态（按侵入性排序）

### A. 浏览器原生（零依赖、与仓库哲学一致）

- **`CanvasRenderingContext2D.measureText`** / **`TextMetrics`**：逐字 advance、bounding box；可离线算「笔画 bbox → 候选格心」。
- **`document.fonts.load`**：保证与屏上 LXGW 一致后再量测。
- **离屏 canvas + `getImageData`**：与现有 `rasterizeMask` 同思路，做 **距离场（SDF）** 或 **骨架线采样**，再 **Poisson-disk / 蓝噪声** 撒点，比纯随机 shell 更均匀。

### B. 版式思路（不引入 npm 亦可手写子集）

- **Knuth–Plass 类断行**（过杀于单巨字，多行 macro 时有用）：代价函数 = 行长偏差 + 惩罚项。
- **中文标点禁则**：可做成「macro 预处理」小函数，与形态无关。

### C. 重型方案（需 WASM 或后端）

- **HarfBuzz / ICU**：正确处理 **字形选择、连笔、竖排**；适合「文稿模式」真排版，而不是粒子剪影主循环。
- **Rust/skia-path** 等：生产级轮廓运算，适合若日后脱离「纯静态页」约束。

## 3. 推荐迭代顺序（与现有 `buildTextSilhouetteLayout` 衔接）

1. **布局与运动分离**：`layout` 输出「目标格 `(mgx,mgy)` + 优先级」；`motion` 只读布局，关「动」时 **不写入** 目标格（仅允许叠分 / 合法化）。——本次 `3.33.6` 已向此方向挪了一步（关「动」锁格）。
2. **量测辅助壳**：巨字串先用离屏 `fillText` + alpha mask 得笔画区域，再在区域内 **蓝噪声采样** 得初始 `(tx,ty)`，减少「壳上随机挤成一团」。
3. **可选模块**：`js/ziling/text-layout-bridge.js`（仅 `mega` / `kao` setForm 时调用），主循环零依赖；失败则回落现有算法。

## 4. 何时值得上「组件」

当且仅当：**(a)** 需要与网页其它区域 **同源字符串** 同步排版；**(b)** 要接 **可变内容 API**。否则离屏 canvas + 数据驱动布局表，比嵌入 React 排版组件更贴合本仓库的零构建约束。
