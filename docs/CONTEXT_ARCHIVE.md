## 1. 用户声音（应视为长期约束）

### 1.1 三条原则（人类原话归纳）

人类明确希望后续工作都服从这三条，**且三条同等重要**，实现上要显式权衡：

| 原则 | 用户表述的核心 |
|------|----------------|
| **美观** | 视觉与辨形要好 |
| **流畅** | 用起来顺 |
| **创新性** | 产品有辨识度、不是普通粒子壁纸 |

工程转译见 **`docs/AI_CONTINUITY.md` §1**（表格式，便于 AI 落代码时对照）。

### 1.2 「检阅」与「嵌入」分目标（人类原话归纳）

- **检阅**：人类在 **自己检阅**（桌面浏览器里看效果、调参数）时，希望 **不卡**、跟手。  
- **嵌入 App**：装进 **WebView** 后仍希望 **尽量流畅**。  
- 人类曾说明：**不必先搞懂** Performance 面板等术语；实现上由开发/AI 用 **`?dev=1`**、分段计时、降载策略去落地。

### 1.3 对「换框架」的态度（会话结论）

- 人类曾因卡顿考虑：**嵌入 App 是否要换框架**。  
- **结论（已写入延续说明）**：卡顿主要来自 **主线程每帧算力**，换 React/Vue **不会自动**更流畅；优先 **帧预算、降载、算法**；框架留给「工程变大以后」再议。  
- 若未来要组件化外壳，可采用 **壳框架 + 核心 `pet.js`**，不替代「帧预算第一」。

### 1.4 对文档的期望（人类原话归纳）

- 希望 **越清楚越好**，把 **AI 的上下文总结**、**人类与 AI 对话里有价值的部分** 都放进仓库，**便于后续展开**。  
- 本文档即该需求的承载之一；原则级短文仍在 **`docs/AI_CONTINUITY.md`**。

## 2. 议题时间线（多轮会话合成）

### 2.1 呈现层运动与交互（约 3.35.22–3.35.25）

**人类反馈的现象（归纳）：**

- **待机**：部分字觉得 **偏慢**。  
- **呈现**：字格移动像 **闪现**、**卡顿**；有 **叠字**；**拖字灵不灵敏**；贴边时 **不像橡皮泥挤开**。

**技术侧主要判断（AI）：**

- 呈现剪影格迈曾单独使用「`acc ≥ 1` 才迈一格」→ 易 **积压后同一帧齐跳**（闪现感）。  
- 叠分 **第二遍** 在「非沙拨拖曳」时被整体跳过 → **解耦拖**（`_dragShellDecoupled`）下易 **叠字**。  
- 贴边橡皮泥依赖 `_tickDragWallPhysics`、格迈前 `wx,wy` 形变支路；呈现 + 开内动时可略加强度与 `_wallRegroupK` 响应。  
- 拖曳：`DRAG_THRESHOLD`、解耦拖 **残差耦合** 影响跟手。

**已落地改动（构建索引见 `IMPROVEMENTS.md`）：**

- **3.35.25**：呈现与待机 **共用** `_gridMarchFrameAcc` 的 `floor` 扣减与 `stepBudget`；略抬 `GRID_MARCH_CELLS_PER_SEC`、关内静 `accMul`；解耦拖时 **保留**叠分第二遍；贴边 `clayMul` + 更快 `_wallRegroupK`；残差系数与 `app.js` 拖动阈值调整。  
- 更早的 **3.35.24** 等：叠字 `maxPasses`、换形尾 `_finishMorph`、生命周期 α 等（详见改进表）。

**张力说明（给后续 AI）：**

- 「减轻叠字 / 贴边更明显」往往 **增加每帧工作量**；人类若反馈 **非常卡**，应 **先量**（`?dev=1`）再决定 **减哪一类效果** 或 **加「流畅优先」预设**（原则已确认，产品形态待定）。

### 2.2 原则与接手说明（约 3.35.25 文档波）

- 人类确认 **美观 / 流畅 / 创新性** 为长期原则；**检阅** 与 **嵌入** 分目标。  
- 新增 **`docs/AI_CONTINUITY.md`**，并在 `HANDOFF.md` / `AGENTS.md` / `docs/ZILING_LAYOUT.txt` 互链。

### 2.3 全量上下文进仓（本文档，3.35.26）

- 人类要求：把 **上下文总结**、**双方有价值内容** 写入仓库，**越清楚越好**。  
- 新增 **`docs/CONTEXT_ARCHIVE.md`**（本文），与 `AI_CONTINUITY` 分工：**本文 = 用户声音 + 时间线 + 开放题；`AI_CONTINUITY` = 原则表 + 接手顺序**。

## 3. AI 侧「值钱」的共识与操作习惯（给后续 AI）

### 3.1 工程事实（避免重复踩坑）

- **零依赖静态站**：无 npm、无构建；改 `pet.js`/`app.js` 后靠 **浏览器强刷** + **`?v=`** 与 **`ziling-build`** 对齐版本认知。  
- **真源**：产品叙述以 **`DESIGN.md`** 为准；机制细节以 **`HANDOFF.md`** + 代码为准。  
- **呈现剪影条件**：`isPresentationSilhouetteHarm` = `presentation` + mask 巨字/颜（**不要**把呈现专用逻辑套到待机 `silMaskPet` 上，历史有坑，见 `HANDOFF.md` §4.2）。

### 3.2 性能排查默认路径

1. 开 **`?dev=1`** 看 `_update` / `_render` / 整帧 ms。  
2. 怀疑叠分 / mask：在 `_update` 内对关键段加 **短时计数**（仅开发分支，勿默认污染主路径）。  
3. 嵌入预览：开 **`?mobilePerf=1`** 或构造 `embeddedMobilePerf: true`，对照桌面。

### 3.3 改完交付习惯（Cloud / 人类协作）

- 行为或可见文案变更：**bump `ziling-build` + 所有 `?v=`**；**`docs/IMPROVEMENTS.md`** 与尽量 **`DESIGN.md`** 变更表补一行。  
- 侧栏：同步 **`title`** 与 **`HANDOFF.md`** 控件说明（若有 §12 表）。
